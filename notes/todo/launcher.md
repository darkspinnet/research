# Launcher

- 2026-08-29: `/bug` now reserves its archive name synchronously but writes and compresses the snapshot off the Blaze chat request, preventing high-volume trace capture from holding the client response open; background failures remain visible on server stderr and incomplete temporary archives are removed.
- 2026-08-27: Continued campaigns now bootstrap and repair the native Rooms target on the first chat-open boundary, restoring `/bug`, `/victory`, and ordinary Messaging submission when Continue bypasses the ship-room setup path.
- 2026-08-27: Advanced Play Detached now treats running-client detection as a separate cleanup affordance instead of converting the launch button into a disabled `RUNNING` state, so another Crogenitor can be launched immediately. Its close control enumerates every Game process, preserves PIDs owned by live `attached` process registrations, and stops every detached or untracked PID. A failed cleanup writes each complete PID-specific OS error to the launcher log, returns only the failed-client count to the UI, and clamps the visible Last Run field to two lines while preserving its full hover text. A normal detached exit now shows only `Exited normally.` while retaining its Crogenitor and PID in the launcher log. The detached Crogenitor selection persists across launcher restarts, falling back to the existing alternate-profile selection when no saved preference exists. Darkspinner's loopback authentication broker is now mounted on the existing multiplexed game-server TCP listener, removing its separate port-8090 reservation without a Fang hook; the standalone `darkrun auth` development command retains its existing port.
- 2026-08-24: The rolling `latest` workflow now uses concurrent native Windows and Linux matrix jobs, selects the runner-cached current Go 1.25 patch through `setup-go`'s Node 24 release instead of downloading the exact older `go.mod` patch, provisions the Windows i686 GCC toolchain from the maintained MSYS2 package and exposes it to PowerShell build steps, uploads one platform archive from each, and recreates the release only after both artifacts are available under a unique `latest-<run>-<attempt>` tag; release commands receive the repository explicitly because the artifact-only publish job has no checkout, the prior rolling release and remote tag are removed, GitHub's stable `/releases/latest` route advances, and ordinary pulls no longer conflict with a force-moved `latest` tag. The existing Linux `darkspinner:buildCI` behavior still builds both platforms, while `darkspinner:buildCINative` exists for split CI runners.
- 2026-08-23: Linux launches now preserve Wine stderr in `darkspin/logs/wine.log`, log the complete nonzero launch result, and include launcher state plus JSON client-result records in reports so Linux client exits retain their actionable fault instead of collapsing to a generic error state.
- 2026-08-23: New Crogenitor registration now accepts only 1–20 ASCII letters or digits at both the field and backend creation boundary; the general identity reader remains compatible with existing locally stored names.
- 2026-08-23: Linux/Wayland startup now supplies the embedded spider PNG to GTK and identifies the process as `darkspinner`, allowing the compositor to associate the window with DarkSpinner instead of displaying its generic fallback icon.
- 2026-08-23: Both launcher and `/bug` archives now freeze gameplay-owned report-time metadata rather than inferring it from retained logs; the manifests carry active hero identity and level, resources, squad, XYZ and nearest marker, mission/mode/difficulty, progression, unlock state, and game/session/zone identity, while `/bug` also writes the same summary to `bug.txt` and the canonical structure to `bug.json`.
