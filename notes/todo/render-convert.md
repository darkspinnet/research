# Render conversion

- Current: `darkrun convert <source[:entry]> [destination]` performs strict package/DS conversion or extracts one selected entry, while `darkrun gltf <source[:entry]> <destination.gltf>` exports either the package set or one selected RW4/GMSH asset. The destination remains required except when rebuilding an Audio bundle, which defaults to the `Audio.ds` parent directory. DS normalization upgrades existing definitions through the latest semantic codecs without losing recovered paths.
- Goal: Provide a human-readable, WCE-inspired `.ds` directory that accounts for every package resource and every byte, supports a structurally valid Game-loadable rebuild with the closest practical byte parity, and gives Blender complete editable access without treating glTF as an authoritative representation.

## Decisions

- Treat DBPF as the outer archive. Its members are independently bounded resources identified by exact type/group/instance keys rather than authored filenames.
- Follow Quail's separation of archive, exact binary format, and human-readable definition layers: `DBPF -> RW4/BMDL document -> DS definitions`.
- Make `convert` bidirectional from explicit source and destination arguments, matching Quail's command design. A `.package` source produces a `.ds` directory; a `.ds` source produces a `.package` file.
- Make `gltf` a separate one-way command with explicit source and destination arguments. It may approximate or omit unsupported render semantics, but must report that loss.
- Make package-mode `gltf` create a destination directory containing one independent glTF bundle per projectable RW4 or GMSH resource. Use Quail-style `package:entry` positional selectors for focused inspection, DSE conversion, and glTF projection rather than command-specific ordinal or registry flags.
- Discover a conventional `reg_file.txt` beside the source tree or in the workspace SporeModder-FX cache automatically. Recovered aliases improve paths and selection but are not package identity and never require a command-specific flag.
- Keep DS intentionally verbose, count-led, definition-oriented, easy to diff, and easy to copy and paste. Do not optimize it as a compact generalized scene format.
- Use `.ds` for the converted directory and `.dse` for every resource entry. Follow Quail's recursive `_root.wce` convention as `_root.dse`: the package root owns package metadata and immediate includes, every subdirectory root includes only immediate child roots and records only local resources, and explicit ordinals preserve package order across the distributed indexes. Proven structures use named fields and arrays; unknown authoritatively bounded bytes use explicit editable ASCII rows, with decimal bytes preferred inside decoded resources and hex retained only for outer formats that do not yet have a codec. Do not emit resource `.bin` sidecars, format-specific Pure Data sidecars, or a duplicate `_source.package`; the visible DS definitions and standard editable media must be sufficient to rebuild.
- Mark every schema field that can be absent or null with a `?` suffix. `FIELD? NULL` is an explicit value: its owning typed codec must deterministically omit the optional bytes, encode the format's null reference, or write the proven fixed-width zero representation. Required fields reject `NULL`; opaque or unknown fields never guess null behavior. An empty string, empty array, zero, and `NULL` remain distinct values.
- Keep every DSE declaration a simple one-key/one-value pair, quote every nonnumeric value, and use established property-token spelling without underscores. Known symbolic property types are sufficient declarations: `TYPE "INT32"` maps to binary code `0x0009`, while `TYPE "STRING8"` maps to `0x0012` and requires quoted `VALUE` data. Do not redundantly emit numeric type codes for known types; reserve an explicit numeric code only for a future unknown-type representation.
- Derive property-list array framing from the preserved `FLAGS` bits instead of emitting a redundant `ISARRAY` selector or guessing from `NUMVALUES`. A scalar and a one-element array both have one value, and an array may have zero values.
- Give scalar and array properties distinct fixed declarations. `PROPERTY` always contains aligned `ID`, `TYPE`, `FLAGS`, and exactly one `VALUE`; `ARRAYPROPERTY` additionally contains the encoded `ITEMSIZE`, a required `NUMVALUES`, and that many nested `VALUE` entries. Do not emit scalar `ITEMSIZE 0` or `NUMVALUES 1` fields that are implied by `PROPERTY`.
- Infer byte counts from the packed `HEX` rows and semantic section encoders. Do not serialize a redundant `NUMBYTES` field; owning package and section sizes validate the inferred result.
- Keep the DS definition universe unified so meshes, buffers, materials, skeletons, animations, and references remain human-navigable. Separate Go source files may organize implementation without fragmenting the document model.
- Require strict conversion. Every byte must be consumed by a proven structure or retained inside an authoritatively bounded opaque resource or section. Unexpected trailing data, invalid boundaries, and unaccounted data are fatal.
- Preserve resource ordering, TGI identities, package header fields, entry flags, and every represented payload datum. Recompute offsets, sizes, compression, and other derived archive layout during rebuild rather than retaining a hidden source archive.
- Give every concrete DSE grammar a concise unique declaration that implies its fixed property sequence without a project-name prefix. Ordinary property resources use `PROPERTYLIST`; a combined audio bundle distinguishes package ownership with `AUDIOLIST` and `PROPSLIST`, allowing both to coexist in one same-noun DSE. Specialized declarations are `SNR`, `SNS`, `PD`, `PDR`, `RW4`, `GMSH`, `AUDIOBASE`, and `OPAQUE`; package indexes use `PACKAGE`, `DIRECTORY`, `AUDIO`, `AUDIODIRECTORY`, and `RENDERDIRECTORY`. Type-specific `RW4*` nested declarations remain unchanged, and no grammar uses dynamic `ENCODING`, `FORMAT`, or `KIND` selectors beneath a generic declaration.
- Let one logical asset DSE contain multiple ordered top-level definitions when the package stores companion resources separately. SNR/SNS pairs share one DSE and WAV under their audio category as `SNR` then `SNS`; PD/PDR pairs share one DSE as `PD` then `PDR`. The recursive index retains a separate `RESOURCE` record, ordinal, and TGI for each package entry while both records reference the shared file.
- Treat a GMSH and RW4 resource with the same group and instance as one render asset. Emit one categorized DSE with `GMSH` followed by `RW4`, retain both package resources in the directory index, and keep type folders only for render resources without an exact companion.
- Give decoded-but-unnamed scalars stable schema properties only when their width and position are proven. Preserve wholly unknown bounded structures as editable ASCII hex fields instead of inventing semantics or hiding them in binary sidecars.
- Use stable symbolic definition tags for cross-references in DS. Raw RW4 object indexes, section offsets, and encoded references belong to the exact binary document layer unless reconstruction requires exposing them.
- Follow Quail's reference-tree organization inside each decoded resource: emit a strict `RENDERASSET` definition that gathers a mesh's vertex streams, index data, material links, compiled states, rasters, and raster data without duplicating their authoritative section definitions. Validate this semantic graph during rebuild so it cannot drift from the exact RW4 object graph.
- Sort package entries directly into recovered asset-family and role folders, then explicit `rw4`, `gmdl`, `property`, or unknown-type folders without a generic `resource` prefix. Distributed directory indexes retain authoritative DBPF order and identity; directories and recovered declaration names are human navigation rather than invented package identity.
- Keep glTF downstream of DS-compatible decoded data. Never use glTF as the representation from which RW4 or BMDL is rebuilt.
- Treat shipped game packages and assets as immutable. Generated conversions and diagnostics belong outside the game data tree, with research diagnostics under `bin/game/logs`.

## Quail-derived structure

Quail separates PFS member navigation, extension-selected raw decoders, bounded WLD fragment decoders, and WCE `FromRaw`/`ToRaw` definitions. Darkspin should apply the equivalent hierarchy:

```text
DBPF package
  -> bounded TGI resource
    -> exact RW4/BMDL/GMSH document
      -> bounded typed or opaque section
        -> unified DS definition aggregate
          -> exact binary reconstruction or lossy glTF export
```

RW4 is itself a sectioned object graph. Its header points to a section manifest and section descriptors; descriptors provide type, offset, size, alignment, and type-table identity. Object references may address direct objects, null objects, or manifest subreferences. Section readers must receive bounded payloads and cannot consume adjacent sections.

## Verification contract

- Conversion fails on malformed counts, ranges, references, trailing properties, missing payloads, or unaccounted bytes.
- Unknown outer resources remain exact stored payloads expressed as ASCII hex because the DBPF index supplies authoritative bounds.
- Unknown internal sections may remain opaque ASCII hex only when the enclosing format supplies authoritative offset and size boundaries.
- Production build and direct CLI conversion are the current verification path. Repository policy prohibits creating, modifying, or running tests unless explicitly requested.
